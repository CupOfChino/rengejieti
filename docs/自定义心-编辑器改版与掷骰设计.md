## 1. 需求

### 1.1 属性去重
同一个属性**只能选一次**。已被其它行选走的下拉项要**变暗且点不动**。

### 1.2 「随机抽取」按钮（掷骰子）
在编辑界面加一个按钮，点击后：

1. 先随机决定这次抽**几项**（**2~4 项**，抽的是"除速度外"的属性）；
2. 然后**从速度开始**依次掷骰（调游戏自己的掷骰子 UI）；
3. 掷出的结果就是对应数值；
4. **每次重投消耗 5 点幸运**（和游戏其它重投一致）；幸运不够就不能重投。

速度是固定项、不参与抽取，但**它的数值也用骰子决定**。

### 1.3 数值上限调整
| 项 | 旧 | 新 |
| --- | --- | --- |
| 伤害加成 | 5 | 5（不变） |
| 伤害减免 | 3 | **2** |
| 其它（闪避/意志/神秘学/斗殴/射击/运动） | 30 | **50** |

> 老数据超上限**不静默改**：打开编辑窗时校验提示，不修就存不回去。
> 不打开编辑器 = 不受影响（不会出 bug）。

### 1.4 新增 4 个百分比属性
| 新属性 | 上限 |
| --- | --- |
| 物理伤害减少 % | 50% |
| 法术伤害减少 % | 50% |
| 物理伤害加成 % | 100% |
| 法术伤害加成 % | 100% |

「物理伤害」**只算普通伤害**（游戏里伤害类型只有 普通/爆炸/法术 三种，不含爆炸）。

### 1.5 掷骰与换算（d100，1~100）
| 属性 | 换算 | 骰 100 时 |
| --- | --- | --- |
| 速度 | 骰值本身 | 100 |
| 伤害加成 | ⌈v / 20⌉ | 5 |
| 伤害减免 | ⌈v / 50⌉ | 2 |
| 其它属性 | ⌈v / 2⌉ | 50 |
| 物理/法术伤害减少 % | ⌈v / 2⌉ | 50% |
| 物理/法术伤害加成 % | 骰值本身 | 100% |

**取整规则**：

- 除伤害加成、伤害减免外，结果**四舍五入到最近的 5 的倍数**；
- 百分比项**四舍五入到最近的 10 的倍数**；
- 抽到的数值**不为 0**：普通项最低 5、伤害加成/减免最低 1、百分比最低 10%。

### 1.6 下拉栏改成可滚动
候选属性变多了，下拉栏**一屏只放 6 项**，其余靠**侧边滑动条**滚动。

## 2. 技术方案

### 2.1 新的百分比增减伤用游戏现成机制
`Buff_ChangeAddOrReducePercentOption`（buff 事件选项）：

| 字段 | 用法 |
| --- | --- |
| `ChangeType` | `CauseDamage`＝造成伤害加成 / `BeDamaged`＝受到伤害减少 |
| `ChangeByValue:false` + `Percent` | 按比例增减（0.5 = 50%） |
| `FloorValue` | 保底数值 |
| `DamageTypes` | 限定伤害类型：普通(Ordinary) / 法术(Magic) |

**关键**：它走 `buff.SourceKey` 追踪，`OnRemove` 里 `Remove(SourceKey)` 精确退回——
**不会**出现 `IsTrackSource:false` 那种"每挂一次永久叠一层"的问题（见 `AI协作文档.md` 第 12.1 节）。

### 2.2 掷骰子 UI
```csharp
UIDicePanel.Roll(EDiceShowType rollType, CheckDiceData chekData, bool isLoop,
                 EDiceResult checkDiff, int setValue, PseudorandomDiceResultData pseudo)
```
`CheckDiceData` 有无参构造 + 公开字段（`TypeName` / `CheckValue` / `RollType` / `RewardDiceCount` /
`PunishDiceCount` / `Source` / `RoleAttr` / `HeroAttr`…）。`Source` 传大厅里的 `BattleHelper.SceneHeroInfo`。

**待实测**：大厅/幕间环境下骰子面板能否正常播；重投能不能在大厅里用。

### 2.3 去重与滚动
`SimpleDropdown` 是自己画的（按钮 + 弹出的选项列表，每项是普通 `Button`），所以：

- 去重＝给对应选项 `interactable = false` + 文字调暗；
- 滚动＝给选项列表套一个 `ScrollRect` + 竖向 `Scrollbar`，视口高度 = 6 项。

### 3.1 掷骰的实现要点（后来者看这里）

```csharp
CheckDiceData data = new CheckDiceData();
data.TypeName = "速度";              // 骰子面板上显示的名字
data.CheckValue = 100;
data.Source = BattleHelper.SceneHeroInfo;   // 传进去才会启用"消耗幸运重投"
await PrefabSingleton<UIDicePanel>.Instance.Roll(
    EDiceShowType.None, data, isLoop: true, EDiceResult.Success, -1, null);
int roll = PrefabSingleton<UIDicePanel>.Instance.RollResultValue;   // 最终点数（含重投后的）
```

- `Roll()` 内部会 `while (IsOpen)` 一直等到玩家点确认/关闭，**返回后才是最终点数**；
- **重投是面板自己做的**：`_restartCount` / `_againConsume`（= `BattleConfig.StartConsumeLuck`，
  每次 5 点），根本不用自己写扣幸运的逻辑；
- `setVaule` 参数（第 5 个）填 >0 会**强制点数**（想自己控制结果时用）；不填就由面板自己掷。
- 面板还开着的期间**不能再次调用 `Roll`**（开头就有 `if (IsOpen) return;`），所以要一顆一颗串行掷。
