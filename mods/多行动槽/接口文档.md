# 多行动槽 · 对外接口文档

> 面向其它模组作者。命名空间 `DuoActionSlot`，入口是公开静态类 **`ExtraActionSlotApi`**。
> 设计背景与实现细节见仓库里的 `docs\多行动槽-需求与设计.md`。

## 0. 一句话

战斗里每个角色可以有 N 个行动槽：逐槽选行动、逐槽执行；同一角色的槽共享同一个先攻数字，
行动槽 UI 一字排开、中心对称。默认所有角色只有 1 个槽；多出来的槽来自：

1. **特质【速战速决】**（本模组自带，玩家入口）：苏醒时按速度加槽（≥100 +1、≥300 再 +1）；
2. **本接口**：其它模组查询 / 设置 / 增减任意角色的槽数（含敌方 Boss）。

## 1. 生命周期（调用时机很重要）

| 时机 | 发生什么 | 你能做什么 |
| --- | --- | --- |
| 进入战斗 / 每一幕开始 | 槽数重算（特质 + 本接口的额外槽 + 动态提供者） | `SetExtraSlotCount` / `AddExtraSlotCount` 在这里之前调用，本幕即可生效 |
| 选行动阶段（ActionStage） | 玩家 / AI 逐槽选行动；玩家确认后推进下一个槽 | 监听 `SlotChosen`；用 `GetEditingIndex` 知道正在选第几个槽 |
| 出手阶段（ResultStage） | 同一角色的槽连续执行（槽 1 → 槽 2 → …） | 监听 `SlotExecuted`；用 `IsExecuting` / `IsSlotExecuted` 查询 |
| 离开战斗 / 重开战斗 | 清空所有槽状态 | 事件与查询失效，指针复位 |

- **槽数修改在"下一幕开始"生效**（战斗中调用不会打断当前幕的选择 / 执行）。
- **槽数只增删尾部**：增加的空槽从下一幕开始参与选择；减少时丢弃尾部槽。
- 所有接口在"非战斗 / 没有接管 / 参数非法"时都安全返回默认值，**不会抛异常**给调用方。

## 2. 查询接口

```csharp
// 当前幕的实际槽数（非战斗 / 未知角色返回 1）
int  ExtraActionSlotApi.GetSlotCount(BattleRole role);

// 额外槽数（不含基础 1 个；含 API 记账 + 动态提供者）
int  ExtraActionSlotApi.GetExtraSlotCount(BattleRole role);

// 这个角色当前是不是多槽（没接管过返回 false）
bool ExtraActionSlotApi.IsMultiSlot(BattleRole role);

// 选行动阶段：正在编辑第几个槽（0 起；未知返回 0）
int  ExtraActionSlotApi.GetEditingIndex(BattleRole role);

// 出手阶段：这个角色是不是正在执行某个槽
bool ExtraActionSlotApi.IsExecuting(BattleRole role);

// 某个槽的状态
bool ExtraActionSlotApi.IsSlotChosen(BattleRole role, int index);    // 已选好行动
bool ExtraActionSlotApi.IsSlotExecuted(BattleRole role, int index);  // 已执行过
bool ExtraActionSlotApi.IsSlotSkipped(BattleRole role, int index);   // 本幕被跳过

// 某个槽的行为数据（目标 / 目标类型 / 技能都在里面；不存在返回 null）
BattleActiveBehaviorData ExtraActionSlotApi.GetSlotData(BattleRole role, int index);

// 某个槽的 UI 节点（RectTransform；没接管 / 不存在返回 null）
// —— 外部模组想"每个槽画一条线 / 挂个标记"时用它定位，比如取顶边中点
RectTransform ExtraActionSlotApi.GetSlotAnchor(BattleRole role, int index);

// 一次性拿全部槽的快照（从槽 0 起、和 UI 从左到右一致；非战斗返回空列表）
List<ExtraSlotInfo> ExtraActionSlotApi.GetSlotInfos(BattleRole role);
```

`ExtraSlotInfo` 是纯数据快照（字段：`Index / Chosen / Executed / Skipped / IsEmpty /
ActionType / TargetSelectType / ActionId / Targets`），每次调用当场生成，不会跟着战斗变化。

## 3. 修改接口（按 sourceKey 记账）

```csharp
// 把某个来源的"额外槽数"设为 extra（不含基础 1；负数按 0 处理）
void ExtraActionSlotApi.SetExtraSlotCount(BattleRole role, int extra, string sourceKey);

// 在某个来源上加减（成对使用，重复调用同一个 key 是覆盖 / 累加）
void ExtraActionSlotApi.AddExtraSlotCount(BattleRole role, int delta, string sourceKey);

// 移除某个来源的记账
void ExtraActionSlotApi.RemoveExtraSlotCount(BattleRole role, string sourceKey);
```

- **额外的槽数在下一幕开始时生效**；同一角色多个来源（不同 `sourceKey`）的加值会**叠加**。
- 建议 `sourceKey` 用你的模组名（例如 `"MyMod.BossExtraSlot"`），方便排查。

## 4. 动态提供者（每幕重算时询问）

```csharp
// 注册一个"每幕重算时调用"的提供者：返回该角色本幕应额外获得的槽数（异常按 0 处理）
void ExtraActionSlotApi.RegisterSlotCountProvider(string sourceKey, Func<BattleRole, int> provider);
void ExtraActionSlotApi.UnregisterSlotCountProvider(string sourceKey);
```

适合"槽数随速度 / 血量 / buff 动态变化"的模组：提供者每次重算都会被调用一次，
返回值直接叠加到该角色的额外槽数上。

## 5. 事件

```csharp
// 槽数变化（每次重算且数值变化时触发一次）
event Action<BattleRole, int> ExtraActionSlotApi.SlotCountChanged;  // (角色, 新槽数)

// 某个槽第一次选好行动（玩家确认推进 / AI 选完 / 最后一个槽确认时）
event Action<BattleRole, int> ExtraActionSlotApi.SlotChosen;        // (角色, 槽序号 0 起)

// 某个槽执行完成
event Action<BattleRole, int> ExtraActionSlotApi.SlotExecuted;      // (角色, 槽序号 0 起)
```

- 事件都在主线程触发；处理函数里抛异常只会打日志，不会影响战斗。
- 事件订阅请配对自己的"离开战斗"清理（插件的 `OnDestroy` 或战斗结束事件）。

## 6. 样例：给 Boss 加 2 个槽，并监听它的选择

```csharp
using DuoActionSlot;
using Game;

// 战斗中拿到 Boss（比如从 BattleHelper.FightContent.CurWaveEnemies 找）
BattleRole boss = ...;

// 额外 2 个槽（下一幕开始生效；sourceKey 用自己的模组名）
ExtraActionSlotApi.SetExtraSlotCount(boss, 2, "MyMod.BossExtraSlot");

// 监听它每个槽的选择 / 执行
ExtraActionSlotApi.SlotChosen += (role, index) =>
{
    if (role == boss)
    {
        // index 从 0 开始；GetSlotInfos / GetSlotData 能拿到目标
    }
};
```

## 7. 边界与已知问题（重要）

1. **原版"怀表"等额外行动道具默认只对第一个行动槽生效**：
   本模组把"行动开始 / 行动结束"类 buff 的判定**默认只做一次（首个槽前 / 首槽后）**，
   所以像老旧怀表这种"行动结束后重复上一次行动"的道具，只会以**第一个槽**为基准重复。
   **作者没有实际测试过这个场景**，实际效果未知，可能存在奇怪的问题；
   遇到问题时请把日志一并反馈（日志前缀 `[多行动槽]`）。
   - 配置项 `EachSlotTriggerBuffs = true` 可以让每个槽各触发一次，但**不建议**（可能更乱）。
2. **同一个行动允许重复装**（例如两个槽都选攻击）；配置项 `AllowDuplicateAction = false` 可关闭，
   关闭后重复装会在确认时被拦下并提示。
3. **单槽角色完全走原版**：本模组对"只有 1 个槽"的角色不改变任何行为。
4. **兼容「可视化攻击目标」**：不改那个模组；由本模组在运行时识别并接管多槽角色的箭头绘制。
   可视化模组的方法签名对不上时，会在日志里提示并退回"每个角色一条箭头"，两边都不会跑不起来。
5. 日志统一前缀 `[多行动槽]`；关键节点（槽数重算 / 逐槽选择 / 逐槽执行 / 箭头兼容 / 异常）都会打日志，
   排查时直接搜这个前缀。
