# 自定义播放战斗背景和 BGM · 需求与设计

> **一句话**：给每个调查员配一套「战斗背景 + 战斗 BGM」，进战斗（特质苏醒）或使用
> 【领域展开】行动时自动切换；战斗结束把背景和 BGM 复原。
>
> 状态：**需求已确认（2026-09-30），插件已实现并通过编译，待实机验证**
> 本文是内部资料，**不进上传包**。
> 骨架与「自定义心」同源：幕间行动 → 编辑界面 → 每个调查员一份配置 → 插件在战斗中生效。
> mod 目录：`mods\自定义播放战斗背景和BGM\`

---

## 1. 需求原文（用户 2026-09-30 口径，勿改写）

1. 新建 mod「自定义战斗背景和BGM」，在幕间进行行动、添加自定义的特质。
2. 特质苏醒（＝进入战斗）时自动切换场地背景并播放自定义战斗 BGM。
3. 背景在战斗结束后要能复原；背景可以是视频或图片，**视频循环播放**。
4. BGM 是否循环在编辑时可选：
   - 循环：一直播到战斗结束；
   - 不循环：播放一次后，重新播放**原有的战斗 BGM**。
5. 编辑界面布局（草案）：

```
命名（不可重名）：   [调查员名字] —— [文本输入框]
战斗背景（图片/视频推荐分辨率）：  [上传框]
战斗BGM：  [上传框]      循环播放 [打勾]
（确认按钮）  （取消按钮）
```

6. 编辑界面右侧有和自定义心一样的侧边栏，可以查看当前已定义的配置（带删除）。
7. 资源导入：
   - 战斗背景上传框：只允许 `mp4 / png / jpg`；
   - BGM 上传框：只允许 `ogg / mp3`；
   - 打开系统文件管理器选择文件 → 自动复制到 mod 的资源文件夹；
   - **复制时出现重名 → 取消并提示"资源重名"**。
8. 点确认：名称不重复且资源就位 → 写入一条组合配置记录。
9. 允许"什么都不配"或"只配一项"；运行时读不到内容/资源 → 记 log 并跳过，**保证游戏不中断**。
10. 执行逻辑：
    - 调查员 ID 与配置**绝对一一对应**；特质处于苏醒状态，或使用了【领域展开】技艺后，才切换背景+BGM；
    - 背景切换**不是硬切**，有一个**从右往左展开**的效果；BGM 直接切换；
    - 切换前记录原始背景和 BGM；战斗结束后**比较当前值与记录值，不同才复原**；
    - 这个"原始值记录"**一场战斗只记一次**：战斗开始时先清空旧记录再记录；战斗中多次切换**不重置**记录；
- 多个角色**同时**切换：只让**速度最慢的一名**执行（最慢＝最后出手，后发覆盖先发）；
    - 多个角色**分批**切换：后出手覆盖先出手的内容，同样**不重置**记录。

## 2. 我理解的行为模型（请核对）

### 2.1 幕间

| 幕间行动 | 作用 |
| --- | --- |
| 添加特质（名称待定，建议【领域】） | 给某调查员加上"自定义战斗背景和 BGM"特质（和「自定义心」的添加心特质同款） |
| 编辑自定义战斗背景和 BGM | 打开编辑界面：命名 + 传背景 + 传 BGM + 循环勾选 + 确认/取消 + 右侧已有配置列表 |
| （可选，待定）移除特质 | 摘掉特质并删除该调查员的配置（自定义心有，这个 mod 是否需要请确认） |

### 2.2 编辑界面字段

| 字段 | 说明 |
| --- | --- |
| 命名 | 显示为「调查员名字 —— 〈输入文本〉」（输入框内只填后缀）。**不可重名**（重名不允许保存） |
| 战斗背景 | 上传框。只允许 `mp4 / png / jpg`。选完即复制进背景资源目录 |
| 战斗 BGM | 上传框。只允许 `ogg / mp3`。选完即复制进 BGM 资源目录 |
| 循环播放 | 复选框。只作用于 BGM（视频恒循环） |
| 确认 / 取消 | 确认=校验+落盘；取消=关窗不保存 |

### 2.3 战斗执行（我理解的时序）

```
战斗开始
  ├─ 战斗场景已加载、战斗 BGM 已由游戏设置
  ├─ 清空"原始值记录"，记录当前背景 / 当前 BGM（只此一次）
  └─ 该角色"特质苏醒" 且 有配置 → 执行切换
        背景：右→左展开动画覆盖旧背景；BGM：直接切换（循环 or 单次）

战斗中
  ├─ 角色使用【领域展开】→ 立即执行切换（覆盖上一次的内容；不改"原始值记录"）
  └─ BGM 非循环 → 播完自动恢复"原有的战斗 BGM"（不在此时重置记录）

战斗结束
  ├─ 比较 当前背景/BGM 与"原始值记录"
  ├─ 不同 → 以记录为基准复原（背景=移除叠加层；BGM=切回记录的曲子）
  └─ 清空记录，等待下一场战斗
```

### 2.4 多角色

- 同一时机触发的多个角色：按速度排序执行；**后执行的覆盖先执行的**（最终显示最慢者的配置）。
- 不同时机（分批）触发：同样"后覆盖先"，且**不重置**原始值记录。
- 只有一项配置的角色：有背景换背景、有 BGM 换 BGM；缺失项跳过（保持当前值），不整体中止。

### 2.5 容错

任何环节出错（配置缺失、文件不存在、格式不支持、解析失败……）→ 写 log、跳过本次切换，
**绝不让战斗流程中断**。

## 3. 技术调研结论（已确认，2026-09-30）

> 反编译参考：`temp\decompiled\Assembly-CSharp.decompiled.cs`（约 54 万行）。

### 3.1 战斗背景的真实结构 → 用"叠加层"换背景

- 战斗场景是一整个**2D 精灵场景**（`StreamingAssets\Game\SceneTemplate\ZDCJ_*.txt`），
  所有元素都是 `SpriteRenderer`，按排序层分：`BG`（背景）/ `Chara`（角色）/ `Front`（前景）。
- 战斗相机是**正交相机**，默认视野高度 `2×2.4 = 4.8` 世界单位；场景背景元素约 `9×5`（略大于视野）。
- 结论：**不替换场景素材**，而是在 `BG` 层最底部叠加一层全屏的"自定义背景板"：
  - 图片/视频都渲染在角色和前景**下面**；
  - 战斗结束把叠加层销毁 → 原背景自然复原，**不需要记录原背景内容**（记录只是为了满足"比较后复原"的需求，实际销毁即复原）。
- 排序层名运行时用 `SortingLayer.NameToID("BG")` 取，叠加层 `sortingOrder` 取足够小的负数（比场景里最低的还低）。

### 3.2 BGM 的读写口

- 全局 BGM 在 `AudioManager`（`PrefabSingleton<AudioManager>`）：
  - `AudioManager.CurrentBgm`：当前 BGM 引用（`AudioResourceReference.Key` + `ReferenceType`），**这就是"原始值"**；
  - `AudioManager.SetBgm(AudioClipData)`：加载并播放，**内部硬编码 `loop = true`**（非循环需要我们接管）；
  - `AudioManager.BgmSource`：真正的 `AudioSource`（`loop` / `isPlaying` / `clip` 可读写）。
- 音频文件加载：游戏自带 `ResourceLibraryHelper` 的磁盘加载通道
  （`UnityWebRequest` + `DownloadHandlerAudioClip`，按扩展名选 `MPEG / OGGVORBIS / WAV`），
  **mp3 / ogg 都支持**（游戏自己的 mod 导入功能就走这条路）。
- 战斗结束时游戏自身也会调 `MapContent.BackRoomBgm()` 恢复房间 BGM；我们的复原逻辑要与它配合（谁先谁后待实现时定，判定标准=比较当前值与记录值）。

### 3.3 视频（mp4）

- 游戏自带 `VideoPlayer` 用法样例（`UICustomVideoPanel`）：`url = "file://<路径>"` → `Prepare()` →
  等 `isPrepared` → `Play()`；播放目标是一个 `RawImage`（`RawImage.texture` 接 `RenderTexture`）。
- 我们用同样的路子：`VideoPlayer` + `RenderTexture` + `RawImage`，`isLooping = true`。
- 视频编码：走 Unity 原生解码，**推荐 H.264 编码的 MP4**（Windows 上最稳）。

### 3.4 文件选择器（照抄游戏自己的做法）

- 游戏里有现成工具：`FolderBrowserHelper.SelectFile(Action<string> callback, string filter)`（Comdlg32 原生对话框）。
  游戏自己的"上传预览图"就是用它：`FolderBrowserHelper.SelectFile(cb, "图片文件(*.jpg;*.png)\0*.jpg;*.png")`。
- **取消时回调空字符串**；过滤串格式：`描述\0模式`。
- 所以新 mod 的"上传框"直接复用这个工具，不用自己引第三方库。

### 3.5 触发时机（插件挂点）

| 时机 | 可用的钩子 |
| --- | --- |
| 进战斗、特质挂状态 | `MOD.TraitEvent.ActiveBuffOption.Active`（自定义心同款；此时战斗场景尚未加载完） |
| 战斗场景就绪、战斗 BGM 已设置、开打前 | `BattleFightContent.Run()` 里逐个角色 `TriggerBuffs(EBuffTriggerType.BattleStart)`（反编译 359328） |
| 战斗结束 | `BattleFightContent.TriggerBattleEndEffect()`（`EBuffTriggerType.BattleEnd`）/ `GameWorld.ExitBattle()` |
| 角色使用技艺 | 自定义战斗技艺（BattleSkill 880904 同款格式） |

> 具体做法：战斗开始时由插件统一收集"本场战斗参战且持有特质的调查员"，按速度排序执行切换；
> 【领域展开】技艺由插件拦截使用后触发同一个切换函数。

### 3.6 分辨率建议（游戏支持 1366×768 ~ 4096×2160）

| 素材 | 建议 | 理由 |
| --- | --- | --- |
| 图片 | **1920×1080 / 2560×1440（16:9，PNG 或 JPG）** | 游戏默认分辨率 1920×1080；背景层可覆盖式适配 |
| 视频 | **1920×1080 MP4（H.264）** | Unity `VideoPlayer` 最稳的组合；帧率 30/60 均可 |

### 4.3 插件模块划分（预计）

| 模块 | 职责 |
| --- | --- |
| `Plugin.cs` | 入口、读配置、挂 Harmony、注册数据 |

| `BattlePatches.cs` | 战斗开始/结束/技艺触发的 Harmony 钩子与调度 |

### 4.4 背景展开效果

- 世界空间 Canvas（挂到战斗相机下，sorting layer = `BG`，sortingOrder 取最低），尺寸按相机视野计算；
- 内部用 `RectMask2D` 做裁剪容器，宽度从 0 → 全屏宽度做**从右往左展开**（方向/时长待确认）；
- 图片：`Texture2D`（`LoadImage`）→ `RawImage`；视频：`VideoPlayer` → `RenderTexture` → `RawImage`；
- 结束/复原：销毁整个 Canvas 对象 + 停止 VideoPlayer + 释放 RenderTexture。

### 4.5 BGM 记录与复原

- 记录结构：`{ 原始 BGM Key/ReferenceType, 是否已记录 }`，一场战斗只记一次；
- 切换：注册一条指向本地文件的 `ResourceData` → 构造 `AudioClipData` → `SetBgm`；
  - 循环：保持 `BgmSource.loop = true`；
  - 非循环：`SetBgm` 完成后把 `BgmSource.loop = false`，监控播放结束 → 切回记录的原始战斗 BGM；
- 复原：比较 `CurrentBgm` 与记录值，不同才恢复。

### 4.6 性能与安全

- 视频/图片只在有配置的角色触发时才加载；同一战斗重复切换复用缓存；
- 大量文件读写（复制资源）放在选择资源那一步完成，战斗中只读；
- 任何异常 catch 住写 log，绝不中断战斗。

## 6. 风险备忘

| 风险 | 说明 |
| --- | --- |
| 资源不进上传包 | 玩家导入的图片/视频/BGM 只存在本地；mod 更新换目录会丢，需重新导入 |
| 视频解码依赖 Unity | 只保证 H.264 MP4 稳；其他编码（HEVC/AV1 等）可能黑屏，需要在导入时提示 |
| 大文件卡顿 | 4K 视频解码/大图上传会吃内存，建议限制文件体积（待定，是否需要上限提示） |
| 与其它 mod 冲突 | 排序层压在 `BG` 最底；若其它 mod 也做背景层，谁在上谁在下按 sortingOrder 定（可调） |
| BGM 争抢 | 多个角色/多个 mod 同时切 BGM 时，最终以"最后一次调用"为准（我们按速度排序控制自己的调用顺序） |
