## 2. 游戏接入位置

本次用本地 ILSpy 复核了当前框架导出的 `Assembly-CSharp.dll` 中的 `RoleModel`、`RTECustomAnimConfig`：

- 程序集：`E:/SteamLibrary/steamapps/workshop/content/1477070/2925170762/BepInEx/DumpedAssemblies/Depersonalization-Release/Assembly-CSharp.dll`。
- `RoleModel.PlayFx(string effectName, string animName, bool isLoop, ERolePointType posType)` 为每个模型创建独立对象，挂到选定节点；循环特效加入该模型的 `FxList`。
- `RoleModel.SpriteRender` 是主体图片渲染器；另有 `SpriteAnim`、`Scale`、`Collider`、`Trans_Head/Trans_Center/Trans_Base` 可供测量或回退。
- `RTECustomAnimConfig.LoadConfigAnim()` 会把 `ConfigData.AnimSize` 写入对象缩放，`Start()` 也会调用它；因此创建后的缩放必须考虑初始化时序，不能只在过早的回调里设置一次。
- `RoleModel.PlayFx` 还会执行 `RestTransform(parent)`。旧全量反编译中该扩展会重置局部缩放；实施时应复核当前扩展，并以初始化后的实际尺寸校准，不能盲目再乘一次 0.4。
- 旧全量参考 `temp/decompiled/Assembly-CSharp.decompiled.cs` 可搜索 `BuffData.ReloadBuffFx`、`ClearBuffFx`、`MODHelper.CreatFrameEffect`、`RestTransform`，定位完整的创建/清理链。

实现位于 `mods/自定义心/src/HeartFxWidthFitter.cs`：Harmony 精确挂接上述 bool 重载，在 `FxList` 中为对应特效实例添加组件。
只匹配循环特效、`xin_glow` 或插件配置的帧特效名，并核对 `RTECustomAnimConfig.ConfigData.EffectName`，不按对象名模糊匹配。
默认心和自定义心均走这条播放入口。每个实例在 `LateUpdate` 更新缩放，覆盖初始化/重载造成的大小重置，不修改共享动画配置。

## 3. 历史试用口径（0.1.3，已停用）

1. **按完整帧框宽换算，身体占宽平缓修正，宽高等比缩放**。欧吉精确保留0.4，当前女孩约0.30。
2. 人物优先取 `idle` 的首个已加载帧，其次取模型默认动画；没有标准动画数据的模型只采样一次当前主体，避免攻击帧引起伸缩。仅测主 `SpriteRenderer`，不计阴影、UI、额外子渲染器或心焰自身。
3. 帧框宽=`sprite.rect.width / pixelsPerUnit`，换成世界宽后计算；身体占框比例用alpha≥8的横向范围，仅作小幅修正，不直接决定全部缩放。图集/不可读纹理回退精灵边界并记录日志。
4. 缓存站立图的身体占宽；每0.25秒检查待机图/渲染器变化。无需再扫描心焰20帧才应用缩放。
5. 用目标世界缩放除以心焰当前实际世界缩放，将实例x/y同乘倍率，父级缩放只算一次。重复执行保持稳定。
6. 以人物完整帧底边中心为锚点，连同欧吉原先中心挂点的偏移换算；纤细修正导致心焰缩小时，补偿中心高度以稳定下沿，再整体上移0.10、右移0.05。这两个微调量在世界坐标最后叠加，不随体型或朝向缩放/翻转。保留帧图留白、速度和排序。

### 校准参数与来源

- 本体 `StreamingAssets/Game/RoleModel/Model_NPC_1001.txt`：`Sprite_Render.size=(0.984375,0.875)`，对应63×56、64 PPU；idle的`PointPosDatas`指定中心`(-0.018,0.371)`、底部`(0,0)`。注意数据顶层的`CenterPos.y=0.4356474`不是该idle挂点，不能拿错。
- 女孩为工坊`3253405563`的`Model_Custom_all`：`plugins/XluaMod/main.lua`指定帧框64×80、64 PPU、pivot=(0.45,0)；`ResourcesFramework/Input/all/1-1.png`实际可见宽21像素、高50像素。
- 基础比例：`0.4 × 帧框世界宽 / 0.984375`。身体占宽修正为`coverage^0.2722910492`，指数由两个样本反算：欧吉占框约1，女孩占框21/64，最终目标分别0.4和0.30。coverage限制在0.05～1；以后用户调整女孩目标时应重新拟合，不任意叠加倍率。女孩目标值集中在`SlimReferenceScale`。
- 心焰固定底部基准：当前20张516×638图、100 PPU、中心pivot，alpha≥8的最低底边为自底部起136px，即局部y=-1.83。更换心焰帧图后须重测这一参数。
- 中心高度补偿：`pivotY = 0.371*r + (-1.83)*(0.4*r - 实际心焰世界Y缩放)`，`r=帧框世界宽/0.984375`；补偿后最后添加世界坐标`(+0.05,+0.10,0)`。下沿为角色帧底边加`(0.371-1.83*0.4)*r+0.10`，不会随纤细修正漂移。位置微调值集中在`PositionOffsetX/Y`，不修改原欧吉基准。

`XinEditorPlugin.cs` 注册挂钩及配置 `[特效] 按模型宽度缩放 = true`；关闭后重启可回到旧版固定尺寸。原始数据 `AnimSize=0.4` 未修改。

## 4. 测量时的限制

- 单看 `transform.localScale` 无法覆盖“缩放相同但原始图片尺寸不同”的模型，应测主体渲染尺寸并考虑父级缩放。
- Unity 的 `Renderer.bounds` 是世界坐标包围盒，可作尺寸起点，但不等于人物身体轮廓；透明留白、武器、披风或附加图像可能影响测量。
- 仅测主体，排除阴影、头顶 UI 和心焰自身；否则会出现特效越大、测量越大、再放大的反馈。
- 不应盲信头顶点和碰撞盒。本地样本 `3834157609/.../RoleModel/HongShen_Child.txt` 仍填 `HeadPos.y=0.9`、`ModelBoxColiderSize=(0.6,0.9)`，与数据类默认值相同；未证明它们对应可见身高。
- 图片内直接画在一起的武器、披风、翅膀也会计入宽度。本版未实现人体轮廓识别，也不为不可读纹理做 GPU 回读。
