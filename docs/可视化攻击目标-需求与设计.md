# 可视化攻击目标 · 需求与设计

> **一句话**：战斗中把"谁要打谁"画出来——从出手方的行动槽拉一条箭头到目标的行动槽。
>
> 状态：**v0.1 完成并已准备上传**（2026-09-14 整理需求 → 2026-09-15 拍板 → 2026-09-15 实机验证通过）
> 这份文档是内部资料，**不进上传包**；上传目录里只放 `plugins\`、`Uploader`、`README.md`、`创意工坊图\`
> 本 mod 是**纯插件 mod**（不占任何数据 ID，不新增特质/状态/技能）

---

## 1. 要解决的问题

人格解体里，角色装备好行动之后界面上就只剩一个技能图标，看不出这个行动作用给谁。
3v3 打起来时完全无法预判敌人这一轮打谁，我方也只有在选目标那一刻才知道自己要打谁。

参考《边狱巴士》的做法：速度骰子之间用弧线箭头表示"谁打谁"。人格解体的"行动槽"
＝角色头顶那块牌子（技能图标＋先攻序号），正好对应巴士的速度骰子。

## 2. v0.1 需求

| # | 情况 | 箭头样式 | 起点 | 终点 |
| --- | --- | --- | --- | --- |
| 1 | 敌对 · 单体指向 | **红色实线** | 出手方行动槽 | 目标行动槽 |
| 2 | 敌对 · 范围／随机指向 | **红色虚线**，每个可能目标各一条 | 出手方行动槽 | 各可能目标行动槽 |
| 3 | 友好 · 单体指向 | **绿色实线** | 出手方行动槽 | 目标行动槽 |
| 4 | 友好 · 群体指向 | **绿色虚线**，每个目标各一条 | 出手方行动槽 | 各目标行动槽 |
| 4.5 | **干扰类**（原版非伤害技艺，指向敌人） | **蓝色** | 出手方行动槽 | 目标行动槽 |
| 4.6 | **投掷类** | **红色**（固定） | 出手方行动槽 | 目标行动槽 |
| 5 | **争锋相对**（双方都装备了敌对单体行动，且互为目标） | **两个黄色实线箭头，头对头撞在中间** | 各自的行动槽 | 两者中点 |
| 6 | 以自己为目标（含"自身"类行动） | 不画 | — | — |

### 2.1 补充规则

1. **虚线要有"从起点往终点流动"的动画**，不要求精致，有那个感觉即可；实线不做动画。
2. **争锋相对取代原本那两条红箭头**（不是叠加）。样式见 `参考图`：
   两条黄线各自从自己那一侧的行动槽出发，到两者中点附近收头，**两个箭头头部相对撞在一起**
   （参考图里两个头部是轻微错开的，不需要完全重合）。
3. **多条箭头指向同一目标时收束**：所有指向同一个目标的箭头共用同一个终点，
   并且**只画一个箭头头部**（参考图里多根红色箭杆汇入一个箭头头）。
4. **范围攻击不做"主干分叉"**：巴士有主干是因为它区分主要目标／次要目标，
   人格解体没有这个概念，所以范围攻击就是**每个目标各拉一条独立的虚线**，
   所有虚线共用同一个起点（出手方的行动槽），各自带自己的箭头
   （但落到同一个目标上的仍然按第 3 条收束）。
5. 人格解体的"随机目标"底层就是"以对方全体为范围、再随机决定每段打谁"，
   所以**随机目标一律当范围攻击处理**（虚线），不逐段显示真实落点。
6. **v0.1 不做任何开关**（不写配置项、不做界面、不做热键），固定按本表执行。

## 3. 判定口径

### 3.1 颜色：看**实际目标的阵营**

判定顺序（2026-09-15 改版）：

1. **投掷类** → **红色**（固定，不看目标阵营）；
2. **干扰类**（技能 id 命中固定数组）→ **蓝色**（固定）；
3. 其余按**实际目标阵营**：只要有一个目标与出手方**阵营不同** → **红色**；全部同阵营 → **绿色**；
4. 目标全是自己 → **不画**（需求 6）。

> 按实际目标判色而不是按技能类型判色，是为了兜住游戏里的"敌我通用"类技能（`All_*`）——
> 那种技能的目标要运行时才算得出来，按类型判会画错颜色。

**干扰类的固定数组**（只登记游戏本体的技能 id，mod 新增的不走这张表）：
`7 诱敌`、`11 观察敌人弱点`、`12 妙手`、`14 魅惑`、`28 搜身`、`33 威吓`、
`36 实例分析`、`39 援护`、`42 明察秋毫`、`1002 我要安抚她`、`1006 我要使用医疗`、`1012 给出小费`。
来源：`StreamingAssets\Game\BattleSkill\*.txt` 里 `ActionType=技艺` 且目标为敌人（敌单体／全体／随机）的技能。
改名单只动 `src\ArrowLayer.cs` 的 `InterferenceSkillIds`。

### 3.2 实线／虚线：看**是不是范围**，按技能的目标类型枚举判

（枚举名取自游戏 `ETargetSelect`，14 项全覆盖）

| 游戏枚举 | 含义 | 线型 | 颜色 |
| --- | --- | --- | --- |
| `None` | 无 | 不画 | — |
| `Self` | 自身 | **不画** | — |
| `Enemy_Single` | 敌方单体 | 实线 | 红 |
| `Enemy_All` | 敌方全体 | 虚线 | 红 |
| `Enemy_Random` | 敌方随机 | 虚线 | 红 |
| `Self_Single` | 我方单体 | 实线 | 蓝 |
| `Self_All` | 我方全体 | 虚线 | 蓝 |
| `Self_Random` | 我方随机 | 虚线 | 蓝 |
| `Ally_Single_ExceptSelf` | 除自己外的友方 | 实线 | 蓝 |
| `All_Single` | 敌我单体 | 实线 | 按 3.1 判 |
| `All_Random` | 敌我随机 | 虚线 | 按 3.1 判 |
| `All` | 敌我全体 | 虚线 | 按 3.1 判 |
| `All_Single_ExceptSelf` | 除自己外的敌我单体 | 实线 | 按 3.1 判 |
| `Fixed` | 固定目标 | 实线 | 按 3.1 判 |

### 3.3 争锋相对的判定

当 A、B 满足以下全部条件时，把"A→B"和"B→A"两条红箭头**换成两个黄色箭头**：

1. A、B 阵营不同；
2. A 的行动是敌对单体（`Enemy_Single`），B 的行动也是敌对单体；
3. A 的目标里有 B，B 的目标里有 A。

若只有一边指向另一边（B 打的是 C），照常画红箭头。

### 3.4 端点取不到时的退化

目标倒下、无法行动（`IsUnableAct`）、或那块牌子本来就隐藏时，行动槽位置取不到，
退一步钉在**角色身上**（身体中心），避免箭头指向空处。

## 4. 显示时机

| 时点 | 箭头状态 |
| --- | --- |
| 战斗中，某个角色**装备并确定了行动** | 立刻出现属于它的箭头，并**一直显示** |
| 行动选择阶段（我方还在逐个选） | 已确定的箭头持续显示（含敌方全部箭头） |
| **开始出手（进入行动演出）** | **一次性清除全部箭头** |
| 战斗结束／退出战斗 | 全部清除，不留残影 |

说明与理由：

- 箭头是"本轮开打算盘"用的信息，所以**结算演出开始后就不需要了**，直接全清，
  正好避免演出过程中箭头跟着人乱动。
- 每帧按实时数据重画（不清空已确认的箭头），这样游戏自己的目标变化会立刻反映出来：
  目标在执行前倒下／逃跑被剔除、拦截掩护改指向、被抓取改指向、目标全没了当场重选。

## 5. 技术方案

### 5.1 形态

BepInEx 插件（C#），照抄 `..\mods\自定义心\` 那套骨架：`..\mods\可视化攻击目标\src\*.cs` →
`..\mods\可视化攻击目标\plugins\AttackTargetVisualizer.dll`，
编译脚本 `tools\build.ps1` 直接用 Roslyn + 游戏程序集引用（不联网、不用 csproj）。
本地测试同样走 `-InstallHost <宿主 mod id>` 挂到已启用的 mod 上。

> 插件加载机制见 `AI协作文档.md` 第 10 节。

### 5.2 数据来源

| 要什么 | 从哪拿 |
| --- | --- |
| 本轮所有参战角色 | `BattleHelper.FightContent.SequenceList`（也可靠 `Allies` + `CurWaveEnemies`） |
| 某角色的当前行动 | `BattleRole.CurrentBehaviourData`（类型 `BattleActiveBehaviorData`） |
| 目标列表 | 上面这个对象的 `Targets`（`List<BattleRole>`） |
| 目标类型（单体／范围／自身） | 同一个对象的 `TargetSelectType` |
| 行动是否已结束 | 同一个对象的 `ActionFinish` |
| 角色是敌是友 | `BattleRole.IsAlly` / `IsHero` |
| 出手方／目标的行动槽 | `BattleRole.Model.Hud`（`HUDElement`）里的技能图标节点 |
| 角色身上位置（退路） | `RoleModel.Trans_Center` / `Trans_Head` 的世界坐标 |

`HUDElement` 的界面节点在 `Awake()` 里按固定路径 `Find` 出来，路径见下表：

| 节点 | 路径（相对 HUDElement 根） |
| --- | --- |
| 行动槽牌子根 | `Rect_Scale/Trans_Battle/Trans_SkillShow` |
| 技能图标 | `Rect_Scale/Trans_Battle/Trans_SkillShow/Anim_SkillShow/Button_SkillIcon` |
| 先攻序号 | `Rect_Scale/Trans_Battle/Trans_SkillShow/Anim_SkillShow/Image_ActionOrder` |
| 整块战斗 HUD | `Rect_Scale/Trans_Battle` |

### 5.3 渲染

- 插件自己建一个**专用画布**，挂在游戏 UI 根节点下（`UIRoot.Trans_ChildElement`），
  用与游戏 HUD 相同的渲染方式（Screen Space - Camera + 同一个相机），保证跟着游戏相机走。
- 画布**排序值比行动槽牌子高**（`SortingLift = 10`）：箭头压在行动槽牌子、HP 条、buff 图标这些战斗 UI 之上。
  > 最初是排在牌子**下面**（想跟巴士一样"从牌子底下钻出来"），但实测箭头会被「编辑行动」这类 UI 框挡住，
  > 2026-09-15 按用户要求改成压在 UI 上面。
- 箭头本体用**代码生成的网格**（UGUI 自定义图元），不依赖任何美术素材：
  1. 曲线：二次／三次贝塞尔，用控制点把弧线抬高，形成"抛物线"观感；
  2. 粗细：根部略粗、接近箭头处略收，末端一个三角箭头；
  3. 虚线：沿弧长按固定周期切段，**每帧偏移相位** → 产生"往终点流动"的动画；
  4. 收束：先按"目标"分组，同一目标的所有箭头共用同一个终点坐标，
     并且**只画一个箭头头部**（所有箭杆都指向它），避免几个箭头头叠在一起糊成一坨；
  5. 范围：每个目标一条独立曲线，共用同一个起点（不做主干分叉）。
- 屏幕坐标换算用游戏自己的 HUD 定位口径（把角色世界坐标投到屏幕点，再转成画布局部坐标）。

**当前外观参数**（全部集中在 `src\ArrowSpec.cs` 的 `ArrowStyle` 里，改一个数字就能微调）：

| 参数 | 值 | 含义 |
| --- | --- | --- |
| `LineAlpha` | **0.8** | 整条箭头（含箭头头）的不透明度（0.5 试过太淡，改成 0.8） |
| `LineWidth` | 6 | 箭杆粗细 |
| `TaperRatio` | 0.7 | 箭头那一端收细到原来的 0.7 |
| `HeadLength` / `HeadHalfWidth` | 34 / 17 | 箭头头大小 |
| `ArcFactor` / `ArcMin` / `ArcMax` | 0.30 / 48 / 300 | 单体箭头的弧高＝距离×0.30，钳在 48~300 |
| `DashArcBoost` / `DashArcMax` | **1.6** / **460** | 虚线（AOE）的弧高再乘 1.6、上限抬到 460 —— 抬得比单体高，一眼能区分 |
| `DashLength` / `DashGap` / `DashSpeed` | 20 / 15 / 110 | 虚线的实段、空段、流动速度 |
| `TargetGap` | 10 | 落点从元素上边框再往上抬这么多，免得箭头头被 UI 挡 |

### 5.4 性能

一帧最多 6 个角色、十几条箭头，顶点数几百级，每帧重建网格的开销可以忽略。
不需要做缓存或分帧。

## 6. 本轮调研已确认的游戏机制（结论，别再猜）

1. **目标在"装备行动"那一刻就写进数据了**，不是出手时才定：敌方 AI 选完技能立刻调
   `BattleBaseAI.AutoSelectTarget(...)`，把具体角色写进 `Targets`。
2. **随机目标也是那一刻摇好的**：`Enemy_Random` 分支当场 `RandomRange` 抽一个写进去；
   若技能标了"每段各自随机"，则每段各抽一个。所以随机技能的目标数据是真实目标。
   （但我们按需求只画"可能范围"，不显示真实落点。）
3. **敌方瞬间完成、我方逐个等玩家**：进入行动选择阶段时游戏同时给敌我发"选行动"，
   敌方不需要等人，我方每条都要等你操作。所以观感上"敌方先装备好"。
4. **有四种情况会在演出时改指向**（所以箭头是预告，不是保证）：目标倒下／逃跑被剔除、
   目标全没了当场重选、拦截掩护改指向拦截者、被抓取改指向抓取者。
   因为我们是每帧按实时数据重画，这些变化会**自动**跟着变，不需要额外处理。

## 9.2 写代码时踩到的坑

1. **`BattleRole` / `BattleFightContent` / `EFightPhase` 在 `Game` 命名空间里**，
   不是全局命名空间。而 `BattleHelper`、`HUDElement`、`UIRoot`、`PrefabSingleton`、
   `BattleActiveBehaviorData`、`ETargetSelect` 都在全局。写代码时 `using Game;` 不能少。
   （doc 里第 10 节的老结论"同名枚举散在不同命名空间"就是这件事。）
2. **战斗阶段名和直觉相反**（见下表）——"选行动"叫 `ActionStage`，"开始出手演出"才叫 `ResultStage`。
   文件 `Assembly-CSharp.decompiled.cs` 里 `EnterPhase()` 在 359769，主循环在 359347 附近。

| 阶段 | 实际在干什么 | 箭头 |
| --- | --- | --- |
| `LookStage` | 战斗开始的准备 | 不画 |
| **`ActionStage`** | **选行动**（敌方瞬间、我方逐个等玩家） | **画** |
| `PreprepareStage` | 回合开始的 buff／重置 | 不画 |
| **`ResultStage`** | **出手演出**（`OnCalculationResult` 在里面跑） | **不画（全清）** |

## 10.1 上传包内容（干净版）

上传目录＝`mods\可视化攻击目标\`，里面只该有这几样：

| 项 | 说明 |
| --- | --- |
| `plugins\AttackTargetVisualizer.dll` | 插件本体（必需） |
| `Uploader` | 工坊元数据：标题／简介／标签／预览图路径（必需） |
| `README.md` | 公开说明（打进包里） |
| `工坊简介_中文.txt` / `工坊简介_英文.txt` | **复制用**的简介（跟英文份同格式：Title 一行 + 正文整段）。游戏不读它们，只是上传时手动粘贴用；中文份是从 `Uploader` 解转义生成的，改了 `Uploader` 要重新生成 |
| `创意工坊图\` | 工坊预览图（`PreviewPath` 指向 `1.jpg`） |
| `src\`、`tools\` | 源码与编译脚本（跟「自定义心」一样随包公开；想要最小包可以删） |

**不要**放进上传目录：本文件（内部设计文档，已挪到 `..\docs\`）。
