# 领域文字底板：实现方案调研

2026-11-20 更新：领域展开使用下面的同网格方案，接入了黑色圆角底板和气泡尖角。当前用法与测试范围见 [AI 协作文档](AI协作文档.md) 第 26.7 节。

以下为 2026-11-01 的历史调研记录。当时完成了方案与隔离编译验证。

## 1. 需求与结论

用户希望战斗中展开领域时，头顶文字有类似《边狱巴士》参考截图的对话背景，便于从战斗画面中辨认。
本轮请求是研究实现方案；底板具体轮廓、透明度、是否保留全屏暗角尚未确认。

首选方案：在现有 `EdgeVignetteGraphic` 的同一次网格生成中，追加一块随文字框移动的局部深色底板。
这是基于现有暗角路径已被历史实机记录验证的可行性判断，不能把本轮编译通过说成游戏里已经显示成功。

## 3. 首选实现结构

保留同一个 Canvas 和 CanvasGroup，绘制顺序为：全屏暗角 → 局部底板 → 文字。
底板追加到 Vignette 的网格中，文字仍是独立的后置子节点。
不把新 Graphic 挂到 Text 上，不更换 Canvas 模式，也不恢复已删除的椭圆实现。

1. `Build` 缓存现有 `EdgeVignetteGraphic` 引用；在文字布局和定位完成后更新它的底板矩形。
2. 用 `_boxRt.GetWorldCorners` 取得文字容器边界，再用暗角节点的 `InverseTransformPoint` 转为该网格的局部坐标。
   不把 `anchoredPosition`、屏幕像素和其它节点的局部坐标混用，也不假设 pivot 为中心。
3. `OnPopulateMesh` 先生成现有暗角，再以 `vh.currentVertCount` 为起始索引追加底板三角形。
   最小验证仅加四个顶点、两个三角形，颜色先用明显的不透明测试色，确认可见后改深色。
4. 首次显示、内容变化、分辨率变化、角色或行动框移动引起矩形变化时，调用 `SetVerticesDirty`。
   正式版缓存引用和四角数组；静止时不重复重建，浮动的文字不应让底板跟着逐字抖动。
5. 用现有 CanvasGroup 统一淡入淡出。顶点只保存底板自身透明度，避免把组透明度再乘一次造成淡入期间过淡。
6. 装饰阶段追加局部实心区域与渐隐边缘网格；不要仅在全屏 16×16 暗角网格上改透明度，采样太粗可能漏掉窄文字条。
7. 追加网格前检查坐标有限、宽高有效、索引合法；异常写日志并回退原表现，避免损坏暗角或文字。

建议外观是横向深色半透明文字衬底、边缘柔和，随文字长度伸缩；最终形状和数值属于待确认设计。
现有容器至少 260×80（1920×1080 参考坐标），不能直接认定它就是最终美术尺寸。
需要复核实际可用文字宽度、换行后的高度、后缀上下浮动 6 像素的留白，以及靠屏幕顶端时的完整可见性。

## 5. 实机验证与备选

第一步只验证一块明显的底板能否在文字后面显示；通过后再做柔边与外观。
检查进战斗自动展开、战斗中手动展开、行动框显隐切换、角色移动、长文字换行、分辨率改变和连续切换领域。
文字、底板和暗角应一起淡出；不拦截鼠标，不增加战斗等待或点击继续。

若仍不可见，在显示期间（不是 alpha=0 的淡入起点）记录：最终矩形、顶点数量/非零 alpha、
Canvas 排序、CanvasRenderer.cull/GetAlpha/GetInheritedAlpha、实际材质及 shader；用同一个 Graphic 的全屏测试块作对照。
这些是排查项，不是已确认的历史根因。

备选是复制原版对话框的背景 Sprite/材质到独立底板节点，并自行控制文字和生命周期。
不要直接调用 `RoleModel.ShowDialog` 来替代领域文字：旧反编译参考显示它连接了头像/语音/点击等整套对话逻辑。
尚未定位并验证原版背景资源，也未找到能确认对应用户截图的巴士战斗对话底板；资源复用不是本轮已完成的方案。
