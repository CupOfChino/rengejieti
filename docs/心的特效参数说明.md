## 1. 想要的效果

《人格解体》里一个叫「心」的战斗状态，挂在调查员身上。目标是**还原《边狱巴士》里同名状态（Shin）的视觉**：
角色身后一团金色光芒，丝丝缕缕往上流动，底部更深、顶部更亮，带少量零星亮点。

## 2. 目标游戏的硬限制（最关键）

《人格解体》**没有粒子系统**，mod 只能提供"帧动画"特效：

| 项目 | 说明 |
| --- | --- |
| 特效形式 | 一张一张 PNG 按顺序播（`Game/ExtraAnim/<名字>.txt`） |
| 可调项 | 每帧时长（秒）、是否循环、整体缩放 `AnimSize`、动画速率 `AnimSpeed`、渲染排序层/序号 |
| 渲染 | 单个 SpriteRenderer 换贴图；**没有加法混合、没有噪声模块、没有速度曲线** |
| 挂载点 | 角色身上的固定挂点（我们用的是"身体正中"），特效尺寸以角色为参照 |
| 尺寸换算 | 我们的画布 512×512、`AnimSize=0.302` → 覆盖约 1.55 世界单位；SD 小人高约 1.3 单位（画布上约 429px，1px≈0.00303 单位） |
| 帧数预算 | 64 帧以内没问题（48 帧 512² PNG ≈ 3~7 MB） |
| 播放速度 | 现在 0.2 秒/帧；一圈 48 帧 = 9.6 秒 |
| 排序 | 现在放在角色模型**下面**（`SortName=Chara`、`SortOrder=-100`） |

**所以要做的是：把"粒子效果"翻译成"一段能循环的逐帧动画"。** 关键难点是丝缕感——没有噪声模块，只能用形状/透明度/运动来伪造。

# 第十轮：播放速度修正（2026-09-14，实机反馈）

## 实机反馈

用户：「动画播放速度（切图）太快了，像热血漫的爆气；参考里的心是很慢、像流体一样的光的波动。」

## 根因：`ShowCount` 的单位是 100ms，不是秒

反编译代码（`Assembly-CSharp.decompiled.cs`）里的证据：

```csharp
// PlaySpriteAnimation 取时长时，运行时强制把 IntervalTime 设成 0.1
CurrentAnimation.IntervalTime = 0.1f;
CurDuration = CurrentAnimation.SpriteDatas[_index].ShowCount * CurrentAnimation.IntervalTime;  // 每帧时长
return CurrentAnimation.GetAnimCount() * CurrentAnimation.IntervalTime / AnimSpeed;            // 总时长
```

以及字段本身的官方标签：`[LabelText("播放次数(100ms/次)")] public float ShowCount = 1f;`

也就是说：

```
每帧时长 = ShowCount × 0.1 秒
一圈时长 = (Σ ShowCount) × 0.1 ÷ AnimSpeed
```

我们原来写的是 `ShowCount = 0.2` → **每帧 0.02 秒（20ms）**，48 帧一圈只有 **0.96 秒**。
这和"以为的 0.2 秒/帧、9.6 秒一圈"差了 **10 倍** —— 这就是"爆气感"的真正来源，
不是"快了 2 倍"的问题。`AnimSpeed` 全程都是 1，没有参与这个偏差。

## 修正

`xin_glow.txt` 的 48 条 `ShowCount`：**0.2 → 2**（= 200ms/帧）

```
每帧 0.2 秒；一圈 48 × 0.2 = 9.6 秒（正是最初设计的时长）
```

改完已同步宿主并哈希比对一致；`AnimSpeed=1`、`AnimSize=0.529`、`SortName=Chara`、`SortOrder=-100` 都没动。
**帧图完全没变**（只改显示时长），所以不需要重新生成资源。

## 下次要调速度就改这一个数

| ShowCount | 每帧 | 一圈 |
| --- | --- | --- |
| 1 | 0.1 秒 | 4.8 秒 |
| **2（当前）** | **0.2 秒** | **9.6 秒** |
| 3 | 0.3 秒 | 14.4 秒 |
| 4 | 0.4 秒 | 19.2 秒 |

## 2. 游戏编辑器导入须知（用户导出的 `mods\编辑器测试` 实测得到）

1. **格式兼容**：编辑器导入/导出的特效就是同一份 `CustomSpriteConfigData` txt，我们生成的配置它认。
2. **大坑：编辑器会把 `AnimSize` 重置成 `{x:1, y:1}`**（我们的是 0.529），`ShowCount` 会保留（2 ✓）。
   **不要拿编辑器导出的 `xin_glow.txt` 覆盖项目里那份**；万一手滑，记得把 `AnimSize` 改回 0.529。
3. 编辑器导出**只含 txt**，不带 PNG、也不带 `InternalConfigure.txt` —— 要让它在游戏里真跑起来，项目里必须同时有帧图和注册表（`自定义心` 现在都有）。
4. 编辑器能导入**别的已订阅 mod 的特效**（例如工坊 `3343752458` 的 `GONGSELIZI`「红色粒子」），也能导入**游戏自带特效**。
5. **游戏自带 158 个帧动画特效**在 `StreamingAssets\Game\ExtraAnim\`（`Fire_01..17`、`Flash_*`、`FXFirefly_Light`、`fx_starkey` 等）。
   它们的帧引用长这样——**引用官方图集、不需要自带 PNG**：
   ```json
   "AnimSprite": { "ReferenceType": 1023, "Key": null },
   "IsInternal": true,
   "ResLoadPath": "GameModule/Common/Texture/Fire/fire_pixel",
   "UseAtals": true,
   "SpriteName": "fire_pixel_0"
   ```
   即：想做"用官方素材拼一个新特效"，这条路是通的。
6. 工坊特效 mod 的帧图惯例布局是 `Texture/Effect/<特效名>/<动画名>/<Key>.png`，每个文件带 `.rtmeta`+`.rtview`
   （`.rtmeta` 41 字节且**每个文件各不相同**，里面有各自的哈希，**不能照抄**；`.rtview` 是"文件本体加前缀"）。
   我们用的是 `Texture/ExtraAnim/<Key>.png` **不带**这两个元文件——游戏里能正常加载（F3 已实机），
   但**编辑器不一定能识别**；如果编辑器里我们的帧显示不出来，就在编辑器里重新导入一次帧图，让它自己生成元文件。

## 3. 粒子路线（结论留档）

- **数据层做不到粒子**：buff 的"表现效果"只有两种——`UseFrameEffect=true`（序列帧，我们这条）或 `PrefabResoureReference`（`ReferenceType=Effect`，指向特效预制体）。
- **预制体路线存在**：游戏自己的特效是 Unity 粒子预制体（`Effect/Prefabs/*`），mod 也能自带 `Assets\Resources\Prefabs\Effect\*.rtprefab(+.rtview/.rtmeta)`（工坊 `3343752458` 带了一整套，含 `FX_Buff_101`）。卡点是**怎么造那个预制体**（编辑器导出 / 改造现成的）。
- **插件路线**：BepInEx 运行时 `new ParticleSystem` 也可行（游戏是 URP，需要拿现成材质），但要自己管排序层与生命周期，而且从此依赖插件。
- 注意：参考图那种"慢、像流体"的观感主要靠**运动设计**（低速、低频、低对比），不是"用了粒子就自动有"。
