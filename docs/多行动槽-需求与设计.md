# 多行动槽 · 需求与设计

> 状态：设计定稿（2026-10-04），开始实现
> 模组目录：`mods\多行动槽\`
> 通用知识见 `AI协作文档.md`；可视化模组的锚点细节见 `可视化攻击目标-需求与设计.md`。
> 本文只记"这个模组怎么设计、为什么这么设计、坑在哪"，不抄实现代码。

## 0. 一句话

让任意战斗角色在同一幕里拥有多个行动槽：**逐槽选行动、逐槽执行**；同一角色的所有槽共享同一个
先攻数字；玩家侧通过【速战速决】特质按速度获得额外槽；行动槽 UI 一字排开、中心对称，
且**不改动「可视化攻击目标」**也能让箭头落在整组的对称中心。

## 1. 需求（2026-10-04 与用户定稿）

1. 每个角色默认 1 个行动槽；同一角色的 N 个槽**共享同一个行动顺序数字**（速度位次，最快 = 1）。
2. 选行动阶段：玩家为角色**逐个槽**选行动（选完 A 紧接着选 B，角色不切换），全部槽选完才轮到下一个角色；
   确认后不能回头取消（与原版一致）。
3. 出手阶段：同一角色的多个槽**连续执行**（槽 1 → 槽 2 → …），全部执行完才轮到下一个角色。
4. 槽可以装备不同的行动；**同一行动也允许重复装备**（开关预留，默认开）。
5. UI：N 个槽一字排开、中心对称（奇数居中、偶数分列中线两侧）；**行动顺序数字只显示在最左槽的左上角**。
6. 与「可视化攻击目标」兼容（**不改那个模组**）：箭头指向行动槽组整体的对称中心，而不是最左的数字。
7. 【速战速决】特质（玩家入口）：**苏醒**时，进入战斗时与战斗每一幕开始时按速度重算——
   速度 ≥ 100 获得 1 个额外槽、速度 ≥ 300 再获得 1 个额外槽（最多 3 个槽，含基础槽）；
   **沉睡**：无效果。暮间提供「添加 / 移除」两个入口。
8. 行动槽上限接口层面不设限（其他模组可任意加）；UI 不做压缩排版——
   按"最多 6 个左右、角色一般 1~2 个"设计，其他模组要堆十几个槽就自己改排版。
9. **敌方同样要吃这套系统**——本模组最主要的目标之一是让 Boss 一回合执行多个行动。
10. 对外提供 API，方便其他模组查询 / 设置 / 增减某个角色的槽数。

### 1.1 buff 判定口径（用户 2026-10-04 拍板）

- **默认**：角色级的"行动开始 / 行动结束"buff 判定**只对首个槽做一次**
  （`ActionStart` 在首槽执行前、`ActionEnd` 在首槽执行后），其余槽不触发。
- **预留开关**：`EachSlotTriggerBuffs`（默认关）。打开后每个槽各触发一次；
  **文档与日志都要标注"可能和原版 buff 预期冲突，不建议这样设计"**。
- 槽自身技能数据里的触发（`BattleActiveBehaviorData.TriggeOptionEffect`：
  技能自带的 ActionStart / ActionEnd 效果）属于该行动自己的逻辑，**每个槽照常执行**，不在这个开关的管辖范围。
- **原版"怀表"这类额外行动道具（`Buff_TriggerBattleActionEffect`）因此只对第一个行动槽生效**：
  它在首槽的 `ActionEnd` 上触发一次，"重复上一次行动"重复的就是首个槽的行动。
  **作者未实测该场景，实际效果未知**；后续若玩家反馈异常，需带日志排查（日志前缀 `[多行动槽]`）。

## 2. 结论：必须做插件 + 数据

- 纯数据做不到。游戏本体没有"多行动槽 / 多次选行动"的数据配置项；
  原版最接近的机制是「老旧怀表」的 `Buff_TriggerBattleActionEffect`（行动结束后自动重播上一次行动），
  它既不支持分别选择不同行动，也不支持 UI 多槽。
- 所以本模组 = **BepInEx 插件（战斗流程 + HUD + 幕间）** + **数据（特质、幕间入口）**。
- 这是本仓库第一个动"战斗核心流程"的插件（此前都是 UI / 状态 / 结算层），复杂度最高，必须多轮实机测试。

## 3. 游戏机制调研（实现依据）

反编译参考：`temp\decompiled\Assembly-CSharp.decompiled.cs`（行号随版本变化，按类名/方法名找）。

### 3.1 战斗主循环

- `BattleFightContent.Run()`：战斗主循环，`CurrentPhase` 在 LookStage → ActionStage →
  ResultStage → PreprepareStage 之间转。**注意阶段名和直觉相反**：`ActionStage` = 选行动，
  `ResultStage` = 出手演出（见 `AI协作文档.md` 14.1）。
- `BattleFightContent.EnterPhase(phase)`：每个阶段的具体逻辑。
- 关键时序（每幕）：
  1. `PreprepareStage`（回合开始的 buff / 重置）；
  2. `ActionStage`：**开头** `UpdateControlRoleOnRoundStart()`（同步方法，重建本幕可控角色列表），
     然后对每个角色调 `RoleEnterActionStage(role, callback)`（异步选行动），
     等所有角色选完，`UpdateSkillIconAndActionOrder()` 刷新头顶牌子与先攻数字；
  3. `ResultStage`：开头对每个角色做回合开始结算（`ConfirmNPCFinalTargets` / `TriggerBuffs(RoundStart)` /
     `TriggeOptionEffect(RoundStart)`）→ `CheckActionSequence()` 生成按速度排序的 `SequenceList`
     → `OnCalculationResult()` 逐个角色 `CurrentBehaviourData.Run()` 演出。

### 3.2 选行动

- `BattleRole.ActionSelect(role)` → `OnSelectBehavirAction(role)`：循环等 `IsActionDecision`。
  玩家靠 UI 点击推进（见 3.2.1）；敌人 AI 走 `BattleNpcRole.OnSelectBehavirAction` → `BattleBaseAI.EnterAction`。
- `BattleFightContent.RoleEnterActionStage(role, callback)`：`await role.ActionSelect(role); callback();`
  `ActionStage` 用 `count` 计数等所有角色选完。
- `UIBattlePanel._OnNextPhaseButtonClicked()`（private async Task，由 `OnClickNextPhaseButton()` 调）：
  玩家点"完成选择 / 开始战斗"的收尾逻辑——
  `BattleHelper.FightContent.OnActionOver()`（= `BattleHeroInfo.IsActionSelectionFinish = true`）
  → 找下一个 / 上一个未完成的控制角色，都没有就 `SwitchToShow(ActionPerform)` + `CheckAllAllyActionFinish()`。
- `BattleFightContent.UpdateNextControlRole / UpdatePreviousControlRole`：按 `CurRoundControlRoleList`
  （每角色一条）切换当前控制角色；多槽时**不能**在角色内部切换时用它，否则会跳到别的角色。
- `UIBattlePanel.UpdateNextPhaseButton(role)`：底部按钮文案，按"是否还有别的角色没选"决定
  "完成选择 / 开始战斗"。

#### 3.2.1 玩家视角的 UI 状态机

- `UIBattlePanel.SwitchToShow(EShowType)`：ActionShow（底部按钮）/ ActionSelect（技能菜单）/
  TargetSelect（选目标，`Button_NextPhase` = 底部确认按钮）/ ActionPerform（演出）。
- 选完目标后点确认 → `_OnNextPhaseButtonClicked`（见上）。
- `UIBattlePanel.ClearActionBehaviorSelect()`：清空当前 `CurrentBehaviourData` 并复位 `IsActionSelectionFinish`。

### 3.3 出手顺序

- `BattleFightContent.CheckActionSequence()`：`SequenceList = (存活可行动的我方 + 敌方)`，
  `OrderBy(-Speed)`（LINQ 稳定排序），顺带算 `PriorToSelfEnemyCount`（我前面有几个敌人，供 buff 判定）。
- `BattleFightContent.OnCalculationResult()`：演出循环，逐个 `SequenceList[0]`：
  记录行动信息 → 触发 `ActionStart` → `attackRole.ActionStart()` → `_UpdateHUDSkillShow(true)`
  → `CurrentBehaviourData.Run()`（掷骰、伤害、演出都在里面）→ `SaveRoleSkillSelectRecord`（供怀表"重复上次行动"）
  → `attackRole.ActionEnd()` → `_UpdateHUDSkillShow(false)` → `SequenceList.RemoveAt(0)` →
  等 `BattlePerformPause` → `CheckFightOver`。
- **结论**：多槽只需把"每个角色执行一次 `Run()`"改成"依次执行该角色全部槽的 `Run()`"，
  `SequenceList` 保持角色级不动（先攻数字、`PriorToSelfEnemyCount`、`_UpdateHUDSkillShow` 的语义都不变）。
- `BattleActiveBehaviorData.Run()` 开头会 `Hud.CloseSkillIcon(waitForAnim: true)`——
  多槽时不能让它把整个槽组关掉，HUD 补丁要接住（执行哪个槽就只收哪个槽的牌子）。

### 3.4 行动槽 HUD

- `HUDElement`（`ResourceConfig("UI/Prefabs/Common/HUDElement")`）：
  - 根：`Rect_Scale/Trans_Battle`；行动槽容器：`Trans_SkillShow`；
  - 容器内动画节点：`Anim_SkillShow`（Show / Hide 动画）；
  - 图标按钮：`Anim_SkillShow/Button_SkillIcon`（+ `Image_SkillIcon`）；
  - 先攻数字：`Anim_SkillShow/Image_ActionOrder`（`UIImageSwitch.SetImage(order)`）；
  - "编辑行动"牌子：`Trans_EditorAction`（+ `Anim_EditorAction` / `Text_RoleActionSelect`），
    显示条件在 `HUDElement._UpdateRoleActionOverShow()`：`ActionStage` 且当前控制角色是自己
    且 `Trans_SkillShow` 没显示。
- `HUDElement.ShowSkillIcon / ActiveSkillIcon / CloseSkillIcon / ShowActionOrder`：原版只管理一套。
- `UIBattlePanel.UpdateSkillIconAndActionOrder()`：清空所有角色牌子 →（非 ResultStage 时）重算
  `SequenceList` → 对每个有行动数据的角色 `BattleActionOrder = i + 1` → `ShowSkillIcon` + `ShowActionOrder`。
- `BattleFightContent._UpdateHUDSkillShow(beforeAction)`：每次出手前后按 `CheckCloseSkillIcon()`
  刷新所有角色牌子的显隐。

### 3.5 「可视化攻击目标」的锚点（不改它的关键）

`mods\可视化攻击目标\src\ArrowLayer.cs` → `TryGetSlot()`，三级优先：

1. `hud.Image_ActionOrder.gameObject.activeSelf` → 用**数字图片**的位置；
2. 否则 `hud.Button_SkillIcon.gameObject.activeInHierarchy` → 用**技能图标按钮**的位置；
3. 否则 `hud.Trans_SkillShow` → 用**行动槽容器**的位置（取 `GetWorldCorners` 上边框中点）。

**结论**：多槽角色只要做到——

- 原版 `Image_ActionOrder`、`Button_SkillIcon`（含 `Image_SkillIcon`）**隐藏**（用克隆节点显示各槽图标）；
- `Trans_SkillShow` 保持激活、矩形**中心 = 整组槽的对称中心**（宽度可扩成整组宽）；

箭头就会自然落到 `Trans_SkillShow` 的上边框中点，也就是组中心。**不要动可视化模组一行代码。**

## 4. 详细设计

### 4.1 运行时结构（插件的核心）

每个 `BattleRole` 由 `SlotManager` 维护一份 `SlotState`（`Dictionary<BattleRole, SlotState>`；
战斗结束清空；查不到 = 按原版单槽处理，所有补丁必须能走 null 分支）：

```
SlotState
├─ List<SlotEntry> Slots       // [0] 复用角色原生的 CurrentBehaviourData；[1..] 新建
├─ int EditingIndex            // 选行动阶段：当前在选择第几个槽
├─ int ExecIndex               // 出手阶段：当前执行到第几个槽
├─ int ActionOrder             // 本幕先攻数字（角色级，与所有槽共享）
├─ bool Advancing              // UI 正在推进到下一个槽（防连点）
├─ int LastCalcRound           // 上次重算槽数的幕号
└─ Dictionary<string,int> ExtraSources  // 外部 API 给的额外槽数（按来源记账）

SlotEntry
├─ BattleActiveBehaviorData Data
├─ bool Chosen                 // 已选好行动
├─ bool Executed               // 已执行
└─ bool Initialized
```

- **指针切换是核心手法**：游戏到处读 `role.CurrentBehaviourData`（检定、目标、buff、日志、伤害……）。
  我们让它在"当前正在编辑 / 执行的槽"之间切换，其余原版逻辑完全不用改，每个槽都等于一次完整的原版行动。
- 槽数据初始化（同步）：`data.Self = role; data.RollDice.Role = role;`
  （就是 `BattleActionData.Install` 的全部内容，但它是 async——不要去 await，直接写字段，避免 async 坑）。
- 槽数变化（每幕开始时）：只增删尾部的空闲槽；**当前幕已选好的行动不因槽数变化而丢失**（重算都在选行动之前）。
- 战斗结束 / 退出战斗：把 `role.CurrentBehaviourData` 复位到槽 0，丢弃其余槽，清空 `SlotState`。

### 4.2 槽数计算与刷新时机

```
最终槽数 = max(1, 1 + 特质加成 + API 额外加成)
特质加成（Trait 882001，且 CurrentState == Wake）：
    速度 ≥ 100  → +1
    速度 ≥ 300  → +1（与上一条叠）
API 额外加成：ExtraActionSlotApi 里按来源记账的所有加值
```

- 刷新时机：**patch `BattleFightContent.UpdateControlRoleOnRoundStart`（同步 void）的 Postfix**。
  它在战斗安装时调一次、在每一幕 `ActionStage` 开头（玩家选行动之前）调一次，正好满足
  "进入战斗时 / 每一幕开始时"两个时机，而且是同步方法、没有 async 坑。
- 重算只扫描当前战斗的我方 + 敌方（`Allies` / `CurWaveEnemies`），
  比较 `LastCalcRound` 防重复；槽数变化时打印日志。
- 速度读 `role.Data.Speed`（含 buff 来源的 `ExtraSpeed`）。
- 战斗中召唤出来的角色等没有 `SlotState` 的，按单槽处理；下一幕重算时会补上。
- **不在幕中途重算**：战斗中速度变化只影响下一幕（用户口径）。

### 4.3 选行动（ActionStage）

1. **逐槽选择**：patch `BattleFightContent.RoleEnterActionStage`（async void）——
   自己实现循环：
   ```
   for (int i = 0; i < slotCount; i++) {
       若角色已死亡 / 无法行动 → 跳过剩余槽；
       state.EditingIndex = i;
       role.IsActionDecision = false; role.IsActionSelectionFinish = false;
       role.CurrentBehaviourData = state.Slots[i].Data;
       await role.ActionSelect(role);           // 单槽 = 一次原版选择（玩家等 UI / AI 自己选）
       state.Slots[i].Chosen = true;
   }
   // 恢复指针到首槽，供 ResultStage 角色级逻辑使用
   state.EditingIndex = 0;
   role.CurrentBehaviourData = state.Slots[0].Data;
   callback?.Invoke();  // 用 try/finally 保证一定推进，绝不卡死主循环
   ```
   - 敌方 AI：`ActionSelect` 里 `BattleNpcRole.OnSelectBehavirAction` 会为当前槽选好行动；
     逐槽循环即"AI 每个槽各选一次"。
   - 异常兜底：try/catch + finally 调 `callback`，把失败降级为卡不住的"剩余槽按空行动处理"。
2. **玩家确认推进**：patch `UIBattlePanel._OnNextPhaseButtonClicked`（private async Task）的 Prefix——
   - 先读私有字段 `_isUsingItem / _selectItem / _normalThrowItem / _weaponThrowItem`：
     特殊路径（使用道具 / 投掷）直接 `return true` 交给原版；
   - `CurrentPhase != ActionStage`、单槽、或已经到最后一个待选槽 → `return true` 交给原版；
   - 当前槽目标数为 0（原版会弹"未选择行动目标"）→ 自己弹同样的提示并 `return false`（拦下但不推进）；
   - 否则：标记当前槽 `Chosen` → `EditingIndex++` → 指针切到新槽 → `IsActionSelectionFinish = false`
     → 异步刷新 UI（`SwitchToShow(ActionShow)` → `UpdateSkillIconAndActionOrder()` → `UpdateNextPhaseButton`）
     → `return false`。
   - 用 `Advancing` 标志防连点；异步刷新整体 try/catch。
3. **文案**：patch `UIBattlePanel.UpdateNextPhaseButton` 的 Postfix——
   多槽角色且当前不是最后一个待选槽 → 覆盖成"**确定行动 k/N**"；
   只有一个槽 / 最后一个待选槽 → 保持原版"完成选择 / 开始战斗"。
4. **重复装备开关**：`AllowDuplicateAction`（config，默认 true）。
   关闭时，在选择 UI 阶段把已装在其他槽的行动置灰（参考原版技能按钮的可用性处理；
   找不到现成挂点就退化为"确认时拦下并提示"，实现时实机确认）。

### 4.4 执行（ResultStage / OnCalculationResult）

patch `BattleFightContent.OnCalculationResult`（async Task）：Prefix 返回 false，用我们自己的实现替换
（逻辑照抄原版，只改"角色 → 多个槽"这一层）：

```
while (SequenceList.Count > 0) {
    与原版相同的空转 / 逃跑 / 0.3s 等待逻辑；
    CurActionRole = attackRole;
    state = SlotManager.Get(attackRole);
    槽数 = state?.Count ?? 1;

    for (int i = 0; i < 槽数; i++) {
        if (IsFightOver / CurrentResult != None) break;
        slot = state?.Slots[i];
        if (slot == null) break;
        attackRole.CurrentBehaviourData = slot.Data;
        state.ExecIndex = i;
        if (槽是空的（没选行动）) continue;

        // 与原版一致：记录 actionType / skill / magic / targetType / targets
        触发 ActionStart 事件；
        if (i == 0 || eachSlotTriggerBuffs) await attackRole.ActionStart();   // 默认只首槽
        await _UpdateHUDSkillShow(true);          // 我们自己的等价实现
        await slot.Data.Run();                    // 掷骰 + 伤害 + 演出
        SaveRoleSkillSelectRecord(...);           // 反射调原私有方法（怀表兼容）
        if (i == 0 || eachSlotTriggerBuffs) await attackRole.ActionEnd();     // 默认只首槽
        CurActionRole = null;
        await _UpdateHUDSkillShow(false);
        等 BattlePerformPause；
        if (restart / giveUp / IsFightOver) break;
        await CheckFightOver(true);
        if (IsFightOver) break;
        CurActionRole = attackRole;               // 继续下一槽
    }
    CurActionRole = null;
    SequenceList.RemoveAt(0);                     // 整个角色（全部槽）执行完才出队
    if (restart / giveUp / IsFightOver) break;
    await CheckFightOver(true);
    if (IsFightOver) break;
}
```

- `ActionStart` / `ActionEnd` 的**事件触发**（`GameEventManager`）保持原版每角色一次；
  角色级 buff 触发按 1.1 口径（默认只首槽）。
- 行动中途死亡 / 昏迷：后续槽自然跳过（`Run()` 内部会走 `ClearOnActionEnd` 提前返回），
  列表照常出队，不会卡死。
- `SaveRoleSkillSelectRecord` 是 private 方法，用 Harmony `AccessTools.Method` 反射缓存调用；
  调用失败只记日志、不影响流程（怀表"重复上次行动"会退化为记录最后一槽）。

### 4.5 HUD

`SlotHudView`：每个 `HUDElement` 一个懒加载视图（`Dictionary<HUDElement, SlotHudView>`），只对**多槽角色**启用。

1. **模板克隆**：缓存原 `Anim_SkillShow` 的 RectTransform 参数（anchoredPosition / sizeDelta / anchor / pivot），
   克隆 N 份 `Anim_SkillShow` 挂到 `Trans_SkillShow` 下（第 0 份用于槽 0，原模板 `SetActive(false)`）。
2. **布局**：以"原 `Anim_SkillShow` 的 anchoredPosition"为组中心，
   `offsetX(i) = (i - (N-1)/2f) * (槽宽 + 间距)`；间距取原槽宽 + 像素间隙（实机微调成视觉常量）。
   奇数居中、偶数对称分列中线两侧。
3. **数字**：只给 i==0 的克隆显示 `Image_ActionOrder`（`UIImageSwitch.SetImage(order)`）；
   其他槽的数字隐藏。原 `hud.Image_ActionOrder` 始终隐藏（给可视化模组让路）。
4. **图标**：`ShowSkillIcon` 时由视图写入"当前编辑 / 执行槽"的克隆；每个克隆的 `Button_SkillIcon.onClick`
   重绑为原版的 `hud.OnClickSkillIcon()`（打开角色信息）。
5. **容器**：多槽时把 `Trans_SkillShow` 的 RectTransform 宽度扩成整组宽（中心不动，pivot 补偿到 0.5），
   保持 `activeInHierarchy = true`；原 `Button_SkillIcon` / `Image_SkillIcon` / `Image_ActionOrder`
   `SetActive(false)`。→ 可视化模组 fallback 到 `Trans_SkillShow`，箭头落点在组中心。
6. **显隐**：patch `HUDElement.ActiveSkillIcon / CloseSkillIcon / ShowSkillIcon / ShowActionOrder`——
   多槽角色走视图；单槽角色走原版。`BattleActiveBehaviorData.Run()` 开头的 `CloseSkillIcon`
   在"正在执行第 i 槽"时只收 i 的牌子（视图按 `ExecIndex` 处理），不关整组。
7. **编辑提示**：patch `HUDElement._UpdateRoleActionOverShow`——
   多槽角色在编辑第 i 槽且该槽没有牌子时，把 `Trans_EditorAction` 摆到槽 i 的位置并激活；
   其余情况保持原版。
8. **失败降级**：视图初始化 / 克隆任何一步异常 → 记日志、销毁半成品、退回原版单槽显示（游戏照常能玩）。

### 4.7 对外 API（`ExtraActionSlotApi`，public static）

**完整签名、语义、事件与示例见 `mods\多行动槽\接口文档.md`**（对模组作者公开）。摘要：

- 查询：`GetSlotCount` / `GetExtraSlotCount` / `IsMultiSlot` / `GetEditingIndex` / `IsExecuting` /

- 修改（按 `sourceKey` 记账）：`SetExtraSlotCount` / `AddExtraSlotCount` / `RemoveExtraSlotCount`；
- 动态提供者（每幕重算时调用一次）：`RegisterSlotCountProvider` / `UnregisterSlotCountProvider`；
- 事件：`SlotCountChanged`（槽数变化）/ `SlotChosen`（某槽选好行动）/ `SlotExecuted`（某槽执行完）。

- 修改后如果正在战斗中，标记"下一幕重算"；需要立即生效的场景（例如 BOSS 初见）由调用方在

### 4.9 日志（`[多行动槽]` 前缀）

- 必须打：插件启动 / 补丁挂载、每幕槽数重算结果（角色名 + 速度 + 槽数，变化时才打）、
  每个槽"开始选择 / 选择完成 / 开始执行 / 执行完成"、UI 视图创建与降级、API 修改、异常兜底。
- 详细日志（config 开）：槽指针切换、HUD 布局、UI 刷新时机。
- 原则：**测试时能只看日志就还原一场战斗的槽流程**；出问题时能定位到"哪个阶段、哪个角色、第几个槽"。

### 4.10 容错 / 降级原则（用户强调：错了也要能正常玩）

1. **所有 Prefix 补丁：先 try，异常 → 记日志 → `return true`（走原版）**；绝不把异常抛进游戏主循环。
2. **所有"我们的逻辑"都要能走 null 分支**：没有 `SlotState`、没有池槽、没有视图 → 完全按原版单槽。
3. **主循环推进必须 finally 保证**：`RoleEnterActionStage` 的 callback、`OnCalculationResult` 的
   `SequenceList` 出队都不能因异常卡住。
4. **指针安全**：任何时刻 `role.CurrentBehaviourData` 都指向一个有效的 `BattleActiveBehaviorData`
   （最差也回退到槽 0 原生对象）。
5. **UI 降级**：克隆失败 → 恢复原版节点显示（原节点只是被隐藏，恢复 = SetActive(true)）。
6. **配置总开关**：关掉 `EnableDuoActionSlot` = 插件完全不介入（便于二分排查是不是本插件的问题）。

## 5. 边界与已知风险

- **不改可视化模组**，兼容依赖它当前的三级锚点逻辑；我们通过"隐藏它优先取的两个节点 + 容器居中"实现。
  实机验收：多槽角色头顶点位、箭头落点是否在组中心（奇数=中间槽、偶数=缝隙中心）。
- **AI 多槽**：`BattleBaseAI` 的行动池（`CurrentActionPool`）会被多个槽消耗，Boss 第二、第三个槽
  可能选到默认行动；这是"AI 的自然结果"，实机确认是否需要给 AI 槽位留池（API 可用）。
- **buff 时间轴**：默认口径下，一个角色的"行动开始/结束"类 buff 一回合只判定一次（首槽）；
  但技能自身 `TriggeOptionEffect`、`AfterBattleAction` 等仍在每个槽执行——与"每个槽都是完整行动"一致。
- **同速排序**：`OrderBy` 稳定排序，同速按原始加入顺序；同角色的槽连续执行（用户口径）。
- **游戏更新**：本次实现按当前反编译版本（`Assembly-CSharp`）写；更新后若方法签名变化，
  以日志中的"补丁挂载失败"提示定位，重跑 `ilspycmd` 对照即可。
- **存档**：槽状态全部是战斗内临时数据，不进存档；特质本身走游戏原生特质系统。

## 6. 测试清单（实机）

1. 单槽角色（没特质）：全程行为与原版一致（对照改动前）。
2. 速度 100/299/300+ 三种角色：槽数分别为 2/2/3；每幕开始速度变化后槽数正确变化。
3. 多槽选行动：选择顺序、按钮文案（确定行动 k/N）、不能取消、必须选目标才能确认。
4. 多槽出手：同角色连续执行、行动顺序数字只有最左槽、所有槽执行完才轮到下一个角色。
5. 同速多角色 + 多槽：执行顺序稳定、数字正确。
6. 敌方 Boss 多槽（用 API 临时给敌方加槽）：AI 逐槽选行动、逐槽执行。
7. 可视化攻击目标兼容：箭头落点在组中心；槽 2 个（偶数）/ 3 个（奇数）分别确认。
8. buff 判定：默认只首槽触发（对照开关打开后的差异）；开关日志提醒出现。
9. 异常路径：角色中途死亡 / 昏迷 / 战斗结束 / 逃跑 / 换人；不卡死、不报错刷屏。
10. 重复装备开关：开 / 关两种行为。

### 2026-10-04 首测（4 个问题，均已修复待复测）

> 判断"这是不是玩家控制的角色"**不能用 `RoleData.CanControlAI`**——调查员恒为 false。
> 玩家角色用 `BattleRole.IsHero` 或 `role is BattlePlayerRole`；`CanControlAI` 只代表"可控制 AI 的友方 NPC"。
