# 自定义心 · 附加效果（两行）设计与实现

> 2026-10-18 需求：让「自定义心」像「自定义播放战斗背景和BGM」一样，在编辑器里增加两条
> 「目标 / 触发 / 施加或获得 / 层数」效果。本文记录口径、实现位置和边界，方便后来人改。
>
> 编辑器提示（2026-10-18 用户补充）：**本效果建议谨慎搭配，出错可能导致战斗无法进行，建议完成后找一场战斗测试一下。**

## 1. 用户口径

每个调查员的心可以提供两条可选附加效果，每条包含：

| 字段 | 可选值 |
| --- | --- |
| 目标 | 自己、所有友方、仅限友方、单个敌人、所有敌人 |
| 触发 | 行动轮开始、行动轮结束、攻击命中后、行动前、行动后 |
| 施加/获得 | 游戏本体与所有已加载 mod 的状态（buff/debuff），带搜索 |
| 层数 | 非负整数；0/空表示不启用这条 |

另外：

- 状态列表照搬自定义BGM 的收集方式（`BuffFactory.All` + `LoadFileDatas` 逐个 `GetConfig`）；
- 自定义BGM 的预设默认不出现；检测到它的插件已启用后才显示；
- 只要配置了效果，保存时弹“数据相关、后果自负”确认；
- 状态本身有问题时，不能把游戏带崩：保存时能拦就拦，运行时至少跳过这一条效果。

## 2. 本实现采用的精确口径

### 2.1 触发映射

| 界面文字 | `EBuffTriggerType` | 说明 |
| --- | --- | --- |
| 行动轮开始 | `BeforeRoundStart` | 和自定义BGM 每轮施加效果用的是同一时点 |
| 行动轮结束 | `RoundEnd` | 回合结算末尾 |
| 攻击命中后 | `Damage` | 攻击者结算伤害后；`BeHitRole` 为本次被打中的角色 |
| 行动前 | `ActionStart` | `BattleRole.ActionStart` |
| 行动后 | `ActionEnd` | `BattleRole.ActionEnd` |

### 2.2 目标映射

| 界面文字 | `BaseBuffOption.EBuffOptionTargetType` |
| --- | --- |
| 自己 | `BuffTarget` |
| 所有友方 | `AllAlly`（含自己） |
| 仅限友方 | `AllAllyExceptSelfAndBackUp`（不含自己与后备） |
| 单个敌人 | 命中触发用 `BeHitRole`；其它触发用 `RandomNotDeadEnemy` |
| 所有敌人 | `AllEnemy` |

### 2.3 层数

- 普通状态：`Buff_BuffChangeOption(Add)` → `Buff_BuffLayerOption(+N-1)`，和自定义BGM 的
  `AddBuffLayers` 一样假设首次 `AddBuff` 自带 1 层；
- 预设：为每条预设效果生成一个隐藏状态，`MaxLayer = 配置层数`，百分比在生成时按
  `层数 × 10%` 写死；重复触发不会无限叠加，角标层数和实际百分比一致；
- 预设状态不会像自定义BGM 的领域效果那样回合结束自解，而是和普通状态一样持续到
  目标死亡/战斗结束；触发只负责把层数补到配置值；
- 负数在输入框里直接过滤，存档读取时也会归 0。

### 2.4 预设范围

只列自定义BGM 里**按层数**的 8 个预设：

`物理伤害强化 / 物理守护 / 物理伤害弱化 / 物理易损 /
法术伤害强化 / 法术守护 / 法术伤害弱化 / 法术易损`

编号沿用 `DomainEffectPreset`：2、3、11、12、5、6、13、14。预设默认不显示；
`HeartBuffCatalog.HasCustomBattleBg()` 检测到 BepInEx 插件
`codex.depersonal.custombattlebg` 已启用时才加入下拉框。

如果玩家曾经选过预设、后来取消订阅，本插件仍能按同样规则生成隐藏状态（图标回退到
`xin_icon`），不会因为缺少 CustomBattleBg.dll 而报错。

## 3. 实现位置

| 文件 | 职责 |
| --- | --- |
| `src/HeartModel.cs` | `HeartEffect`、目标/触发枚举、预设常量、效果文字、描述拼接 |
| `src/HeartStore.cs` | 两条效果的读写（`Effect1*` / `Effect2*` 键）与隐藏状态编号 |
| `src/HeartBuffBuilder.cs` | 把效果编译成心的 `BuffEventData`；预设隐藏状态生成；单条容错 |
| `src/HeartBuffCatalog.cs` | 状态列表收集、预设可见性、状态校验、后台预加载 |
| `src/HeartSearchDropdown.cs` | 可搜索的状态下拉框（从自定义BGM 的 SearchDropdown 改造） |
| `src/HeartEditorWindow.cs` | 两行 UI、层数输入过滤、回显、保存警告 |

运行时没有新增 Harmony 钩子：效果直接写在心的 `Config.Events` 里，由游戏自己的
`BuffData.TriggerBuff` 按触发节点执行。这样可以保证行动前/后等时点的顺序与游戏一致。

### 3.1 加载性能（2026-10-18 用户特别要求）

照搬自定义BGM 的预加载，并多做两层缓存：

1. 游戏就绪后 `HeartBuffCatalog.PreloadAllBuffsCo()` 每帧读 4 个 `LoadFileDatas`，把游戏本体
   的几百条状态读进内存；
2. 预加载完成后调用 `BuildNormalChoices()`，把“状态编号 + 名称”缓存到 `_normalChoices`，
   打开编辑窗时不再逐条 `GetConfig`；
3. 编辑窗建好后 `HeartEditorWindow.WarmUpEffectDropdowns()` 每帧给两个状态下拉框各建 40 个
   列表项，分帧完成，避免第一次点开下拉框时集中创建几百个 UGUI 按钮。

日志中可搜索：

- `心效果状态表预加载开始 / 完成`
- `心效果状态缓存`
- `心效果下拉框预构建完成`

## 4. 容错与拦截

1. **保存时**：普通状态必须能在 `BuffFactory` 里找到，且不能是自定义心/自定义BGM 的
   运行时状态；找不到就提示并阻止保存。
2. **注册时**：每条效果单独 `try/catch`；某条生成失败只写日志、跳过，心本体仍然注册。
3. **运行时**：状态不存在时 `ResolveEffectBuffId` 返回 0，不把无效 ID 写进事件；
   心本体的属性、维持/解除事件不受影响。
4. **防递归**：普通状态不能指向这颗心自己的本体状态或它的预设隐藏状态。
5. **精神值**：效果事件带“精神值不处于衰弱/衰竭”的检查，和心本身的维持规则一致。

### 4.1 心结束时的自清理（2026-10-18 用户补充）

心 buff 被移除时（战斗结束、精神值衰弱/衰竭解除、倒下、手动移除），
`HeartEffectCleanupOption.OnRemove` 会对“自己 / 所有友方 / 仅限友方”的效果按状态 ID
执行 `RemoveBuff`，移除全部层数。实现方式是把清理选项放进心的一个 `Stable` 事件里，
利用游戏 `BuffData.RemoveBuff` 会遍历所有 `Config.Events.Funcs` 调 `TriggerRemoveOpts`
的特性，不新增 Harmony 钩子。

- 敌人目标（单个敌人 / 所有敌人）不主动清，保留其原有 debuff 生命周期；
- 这是**按 ID 清空**：如果同一个状态还有别的来源，也会一起被移除；
- 目标集合在清理时按当前阵营重新取，离开队伍/已经倒下且状态已被游戏清掉的角色不会强行补删。

## 5. ID 与上限

- 普通状态效果不额外占 buff 编号；
- 每条预设效果占一个隐藏状态编号，仍从 `880910-880999` 分配；
- 因此最坏情况（每颗心两条预设）会把可容纳的自定义心数量从 90 降到 30；
  普通状态效果不受影响。若以后要扩段，先更新 `docs\模组清单.md` 再改
  `HeartConstants.CustomBuffIdMax`。

## 6. 验证清单

- 只改速度/属性、不填效果：保存不应弹数据警告，心行为与旧版一致；
- 选普通状态 + 层数：保存弹警告；确认后下一场战斗按触发时点施加；
- 选「单个敌人 + 攻击命中后」：只给被打中的敌人挂层；
- 选「所有友方 / 仅限友方」：检查是否包含自己；
- 选预设（启用自定义BGM 时）：列表出现 8 项，层数角标与实际百分比一致；
- 关掉自定义BGM 后重开：旧预设配置仍显示并能运行；
- 选一个状态后停用对应 mod：保存被拦截；若存档里已有失效引用，战斗只跳过该条；
- 两条效果同时配置、其中一条失效：另一条仍然生效。
